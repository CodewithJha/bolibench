# ElevenLabs speech round-trip

`bolibench.speech.SpeechAdapter` puts speech between the case and the agent. For each user turn:

```
case utterance --TTS--> audio (mp3) --STT--> transcript --> inner agent adapter
```

The inner adapter (webhook, scripted, or any `AgentAdapter`) only ever receives the transcript. The
evaluator does not change: it still judges the sandbox-observed tool calls and final state, and it
does not depend on which provider made the audio or transcript.

Status: **verified live on 2026-10-18** (free tier, `eleven_multilingual_v2` + `scribe_v2`): real TTS,
real STT, the CLI path with the audio cache, and one end-to-end run where a local agent acted on the
transcripts. See "Verified results (2026-10-18)" below. It is also tested offline against fakes and a
local HTTP stub that answers in the documented request/response shapes.

## What it measures, and what it doesn't

It measures:

- whether a code-switched Hindi-English or Awadhi request still leads to the right action after a
  speech round-trip
- what the speech-to-text model heard. Each turn records the transcript next to the original text, so
  you can see where a word was misheard (for example कल heard as परसों) and what the agent did with it.

It does not measure:

- **Real speakers.** The audio is generated by text-to-speech. It does not have real accents, real
  noise, phone-line codecs, disfluencies or speaker variety, so results show synthetic speech
  robustness only, not field accuracy.
- **Awadhi pronunciation.** ElevenLabs lists Hindi as supported, but not Awadhi. Nobody has checked
  how the TTS reads Awadhi Devanagari (for example ओका, कइ दें, रहेन). A native speaker should listen to
  the saved audio before anyone draws conclusions from Awadhi cases.
- **The agent's own speech handling.** BoliBench does the STT itself. An agent that takes audio
  directly is not tested this way.
- **Speech quality.** No word error rate (WER) or audio-quality score is computed. Transcripts are
  evidence for a human to read. They are not scored, and nothing corrects them.

## How the pieces fit

- `TTS` and `STT` are small Protocols, one method each: `synthesize(text) -> bytes` and
  `transcribe(audio) -> Transcript`. Each also has a `config` dict without credentials. Any provider
  can implement them. Tests use fakes.
- `ElevenLabsTTS` and `ElevenLabsSTT` call the HTTP API with stdlib `urllib`, so there are no new
  dependencies. The official SDK isn't needed for two POST requests.
- Each request is tried once: no retries and no redirects (a redirect would send the key to another
  host). Timeouts are bounded (TTS 30 s, STT 60 s by default) and responses have size limits (5 MiB of
  audio, 1 MiB of JSON).
- Any HTTP or network failure raises an `AdapterError`, such as `elevenlabs stt HTTP 429: Too many
  requests`. The reason is the error's `detail.message` (or the first `detail[].msg` of a 422
  validation error), cut to 200 characters; never the key. The runner then gives the case an `error`
  verdict, never `fail`. A provider outage is therefore never counted against the agent.
- An empty transcript (silence, or audio STT could not read) is passed to the agent as an empty
  utterance, not raised as an error. It is a speech round-trip result: the case will usually `fail`,
  and the artifact shows `asr_text: ""` next to the original text, so the cause is visible. A
  transcript that differs from the utterance is also passed through unchanged.
- `ElevenLabsTTS` and `ElevenLabsSTT` keep the key out of `repr`. `bolibench.speech` is imported only
  when `--speech` is given, so text-only runs never load it or read `ELEVENLABS_*` (tested in a fresh
  interpreter).

### Evidence per turn

`SpeechAdapter.turns` holds one `SpeechTurn` per turn of the current case: the original utterance,
the transcript text, the detected language and its probability, the audio byte length and sha256, the
audio file path (when an audio directory is used), and the TTS and STT call durations. `tts_s` is
`null` when the audio was reused from the audio directory.

The adapter changes the agent's identity in `AdapterInfo`:

- `name` becomes `speech+<inner name>`
- `config.speech` holds `{"tts": {provider, model, voice, output_format, seed}, "stt": {provider,
  model, language}}`

These are part of the summary's `config_id`, so speech runs and text runs are never grouped together.

The artifacts also get:

- `run.turns[i].asr_text`: the transcript the agent acted on
- `run.turns[i].speech`: the full `SpeechTurn` (omitted in runs without speech, which stay byte-identical)

### Audio directory (audit and cache)

With `audio_dir` (`--speech-audio-dir`), each turn's audio is saved as
`<sha256(tts config, text)>.mp3`. If that file already exists, it is reused instead of calling TTS.
Reruns therefore hear byte-identical audio, and TTS isn't billed again. A different voice, model,
format or seed gives a different key. STT still runs every time. To get fresh audio, use a new
directory. Files are written atomically (a temp file renamed into place, removed if the write fails),
and file names are hashes, so no utterance or id becomes part of a path.

## Setup

1. Create an API key at <https://elevenlabs.io/app/settings/api-keys>. Restrict it to the
   text-to-speech and speech-to-text endpoints and set a credit quota
   ([authentication docs](https://elevenlabs.io/docs/api-reference/authentication)).
2. Pick a voice from your voice library and copy its voice id. Prefer a voice built for Hindi;
   `eleven_multilingual_v2` will speak Hindi with any voice, but accent quality varies. `GET /v1/voices`
   lists, per voice, `verified_languages` entries with `language`, `model_id` and `locale`. On
   2026-10-18, eight premade voices were verified for `hi` / `hi-IN` on `eleven_multilingual_v2`,
   including Sarah (`EXAVITQu4vr4xnSDxMaL`), which the verified run used.
3. Export the variables below in your shell. Don't put them in files that might be committed.

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `ELEVENLABS_API_KEY` | yes | none | Sent only in the `xi-api-key` header. Never logged, never in artifacts or error messages. |
| `ELEVENLABS_VOICE_ID` | yes | none | TTS voice. There is deliberately no default voice. |
| `ELEVENLABS_TTS_MODEL` | no | `eleven_multilingual_v2` | TTS model id. |
| `ELEVENLABS_STT_MODEL` | no | `scribe_v2` | STT model id. |
| `ELEVENLABS_STT_LANGUAGE` | no | unset (auto-detect) | Language hint for STT, e.g. `hin`. Auto-detect is the fairer test for code-switching. |
| `ELEVENLABS_BASE_URL` | no | `https://api.elevenlabs.io` | Documented alternatives: `https://api.us.elevenlabs.io`, and data residency `https://api.{eu,in,sg}.residency.elevenlabs.io` (e.g. `in` for India). Must be https. |

The whole config is checked before any network call: a missing key or voice, a malformed id, a
non-https base URL or a non-positive timeout. Through the CLI, any of these is an input error (exit
code 2) and no case runs.

## Running

Python API:

```python
from pathlib import Path
from bolibench.runner import run_case
from bolibench.speech import SpeechAdapter, elevenlabs_from_env
from bolibench.webhook import WebhookAgentAdapter

tts, stt = elevenlabs_from_env()
with WebhookAgentAdapter("http://127.0.0.1:8000/turn") as agent:
    adapter = SpeechAdapter(agent, tts, stt, audio_dir=Path("audio-cache"))
    record = run_case(case, adapter)
    print(adapter.turns)  # per-turn speech evidence
```

CLI (a missing or bad config exits 2 before any case runs; so does `--speech-audio-dir` without `--speech`):

```bash
uv run bolibench run suites/orders --agent-url http://127.0.0.1:8000/turn \
    --speech elevenlabs --speech-audio-dir audio-cache
```

`--speech` also works with `--scripts`. The scripted adapter ignores what it hears, so that run tests
only the round-trip itself: it fills `asr_text` for every case, and the verdicts are the same as a
text-only run.

## Cost

- TTS is billed per character of text and STT per duration of audio. Rates depend on your plan and
  model: see <https://elevenlabs.io/pricing/api>.
- `suites/orders` currently has 12 cases, 14 user turns and 526 characters in total. A full run is
  about 526 TTS characters plus roughly a minute of STT audio.
- `--speech-audio-dir` removes the TTS cost of reruns. STT is billed on every run.
- Don't turn on STT extras such as `keyterms` or `transcript_edit`. They cost extra, and they would
  bias or correct the transcript, which defeats the measurement.

## Verified results (2026-10-18)

Setup: a free-tier key that had been scoped by permission. It answered `401` on `GET /v1/models`, but
TTS, STT, `GET /v1/voices` and `GET /v1/user/subscription` all worked. Voice: Sarah
(`EXAVITQu4vr4xnSDxMaL`, premade, verified `hi-IN` on `eleven_multilingual_v2`). TTS model:
`eleven_multilingual_v2`, format `mp3_44100_128`, no seed. STT model: `scribe_v2`, auto language
detection, `tag_audio_events=false`.

| Layer | Result |
| --- | --- |
| Auth | PASS. `xi-api-key` was accepted for TTS, STT, voices and subscription. `/v1/models` returned 401 for this key's scope; BoliBench doesn't use it. |
| TTS | PASS. `200`, `audio/mpeg`, ID3 mp3, 47,272 bytes for the 48-character Awadhi turn. The `character-cost` response header was `48`, so one character is billed per character of text. No `language_code` is needed. |
| STT | PASS. The multipart `speech.mp3` / `audio/mpeg` upload was accepted. `text` held only the words. `language_code` was `hin`, with probability 0.85 to 0.99. |
| Errors | PASS. Live error bodies are parsed into readable reasons: `HTTP 404: A voice with voice_id '…' was not found.`, `HTTP 400: 'scribe_v0' is not a valid model_id. Available models: …`, `HTTP 400: File is corrupted. Please ensure it is playable audio.` |
| Live test | PASS. `BOLIBENCH_LIVE=1 uv run pytest -q -s tests/test_speech.py -k live` gave `1 passed`. |
| CLI and cache | PASS. Three cases (`awadhi-cancel-yesterday`, `codeswitch-cancel-kurta`, `similar-items-kurta-kurti`) ran with `--scripts --speech elevenlabs`, and a rerun reused the audio: 3 mp3s named `<sha256>.mp3`, `tts_s: null` on the rerun, and identical audio sha256 and transcripts. |
| End to end | PASS for the pipeline. The `examples/ollama_agent.py` agent (`qwen3:8b`, local Ollama) acted on the transcripts: 1 pass, 2 fail. Speech did not cause the fails (see below). |

Cost: 239 TTS characters (48 for the probe, 48 for the live test, and 143 for the three cases, whose
audio was then cached). The account's character counter went from 2,272 to 2,541, so 269 in total; the
other 30 are most likely the STT usage of about 11 clips of roughly 3 to 4 seconds each (not
confirmed). The scripted and end-to-end reruns used no TTS characters.

What the transcripts showed (utterance, then transcript):

- Awadhi `ऊ वाला order जउन कल मँगाए रहेन, ओका रद्द कइ दें।`
  - cached audio: `उ वाला order जो उन कल मंगाये रहे हैं, ओ का रद्द कइ दें?`. The Awadhi forms were
    turned into Hindi (जउन → जो उन, रहेन → रहे हैं, ओका → ओ का). कल survived. The request became a
    question.
  - a separate TTS take of the same text (probe): `उ वाला order जो उन कल मंगाये रहे हैं, वो कर द के दे।`.
    **रद्द (cancel) was lost**, so the request no longer says what to do.
  - the live test's take: `उ वाला order जुन कल मंगाये रहें ओकर रद्द कइ दें।`.
  - Unseeded TTS gave three different audio takes of one text, and STT read each one differently.
    Only cached audio makes a speech run repeatable.
- `मेरा Kurta वाला order cancel कर दो please, अब नहीं चाहिए।` became `मेरा कुर्ता वाला order cancel कर दो please। अब नहीं चाहिए।`.
  The Latin-script `Kurta` came back in Devanagari as कुर्ता; `order`, `cancel` and `please` stayed Latin.
- `कुर्ती वाले order की quantity 2 कर दो।` became `कुर्ती वाले order की quantity two कर दो।`.
  The digit came back as the English word `two`. कुर्ती stayed कुर्ती, not कुर्ता.
- No case contained an order id, so how STT handles ids like `ORD-401` is still untested.

Verdicts with the local agent, speech run compared with a text-only run of the same three cases
(`runs/elevenlabs-qwen3-8b-2026-10-18`, `runs/elevenlabs-qwen3-8b-text-baseline-2026-10-18`):

| Case | Speech | Text only | Cause |
| --- | --- | --- | --- |
| `awadhi-cancel-yesterday` | fail: asked which order | fail: listed orders, then asked which order | the agent can't resolve कल to the 2026-10-16 order, with or without speech |
| `codeswitch-cancel-kurta` | pass | fail: asked for an order id without listing orders | one sample of a non-deterministic model; this doesn't show that speech helped |
| `similar-items-kurta-kurti` | fail: updated ORD-701 (Kurta) | fail: the same wrong call | the agent confuses Kurta and Kurti; the transcript kept कुर्ती |

With n=1 per case on a non-deterministic model, this shows the pipeline works and gives transcript
evidence. It is not a speech-robustness score. The scripted run's 3/3 pass says nothing about
understanding, because the scripted adapter ignores what it hears.

Artifacts (gitignored, under `runs/`): `elevenlabs-audio-2026-10-18/` (3 mp3s),

`elevenlabs-qwen3-8b-text-baseline-2026-10-18/`. A byte scan of all of them, and of every tracked and
untracked repo file, found no key. Every speech turn has `asr_text` equal to `speech.transcript.text`,

## Live verification procedure

Cost of the whole procedure: under 200 TTS characters and well under a minute of STT audio.

1. Set the key and voice without writing them to shell history or files:

   ```bash
   read -rs ELEVENLABS_API_KEY && export ELEVENLABS_API_KEY
   export ELEVENLABS_VOICE_ID=<voice id from https://elevenlabs.io/app/voice-library>
   ```

2. One TTS and one STT call, through the real clients:

   ```bash
   BOLIBENCH_LIVE=1 uv run pytest -q -s tests/test_speech.py -k live
   ```

   Expected: `1 passed`, and three printed lines: `utterance:` (the Awadhi case text), `transcript:`
   (non-empty, mostly Devanagari) and `language:` (likely `hin`, with a probability). It is skipped
   unless the key, the voice id and `BOLIBENCH_LIVE=1` are all set. A `401` means a bad key, `402`
   no credits, `404 voice_not_found` a bad voice id.

3. The CLI path, twice, into a scratch directory:

   ```bash
   for n in 1 2; do
     uv run bolibench run suites/orders/ambiguous-previous-order.json \
       --scripts examples/scripts/ambiguous-previous-order.json \
       --speech elevenlabs --speech-audio-dir /tmp/bb-audio --output /tmp/bb-speech-$n
   done
   ```

   Expected, each run: `speech: elevenlabs TTS -> STT ...`, then `pass  ambiguous-previous-order`
   and exit code 0. The first run writes two `.mp3` files to `/tmp/bb-audio`; the second writes none.
   Check:

   ```bash
   python3 -c "import json,glob; [print(n, [(t['asr_text'], t['speech']['tts_s']) for t in json.load(open(f))['run']['turns']]) for n in (1, 2) for f in glob.glob(f'/tmp/bb-speech-{n}/*/ambiguous-previous-order.json')]"
   rg -l --fixed-strings "$ELEVENLABS_API_KEY" /tmp/bb-speech-1 /tmp/bb-speech-2 /tmp/bb-audio || echo "key not in outputs"
   ```

   Run 1 shows the transcripts with a number for `tts_s`. Run 2 shows `tts_s` `None`, because the
   audio was reused. The `rg` must print `key not in outputs`.

4. Listen to `/tmp/bb-audio/*.mp3`, and to the Awadhi case's audio if you run it, and write down what
   you hear.

Evidence to keep for the write-up: the terminal output of steps 2 and 3, a screenshot of the
ElevenLabs dashboard's usage view showing the characters and STT time used that day, and the transcript next to the utterance from one artifact. Don't screenshot the
API keys page.

Confirmed live on 2026-10-18 (the stub follows the docs, but it isn't ElevenLabs):

- STT accepts the multipart upload sent as `speech.mp3` / `audio/mpeg`, and with
  `tag_audio_events=false` `text` holds only the spoken words.
- The TTS endpoint accepts `eleven_multilingual_v2` without `language_code`.
- Error bodies have the documented `detail` shape (the reason in `AdapterError` comes from it), for
  404 and 400 at least. A 401 or 403 for a key without TTS or STT permission hasn't been seen. If it
  happens, create a key with the Text to Speech and Speech to Text permissions at
  <https://elevenlabs.io/app/settings/api-keys>.

## Key rotation

1. Create a new key in the ElevenLabs dashboard (<https://elevenlabs.io/app/settings/api-keys>).
2. Replace `ELEVENLABS_API_KEY` in your shell or secret store.
3. Run step 2 of "Live verification" with the new key, then delete the old key.

Keys are read from the environment on every run and are never stored or cached by BoliBench, and
cached audio files don't depend on the key. If a key may have leaked, delete it in the dashboard
first. A credit quota on the key limits the damage.

## Limitations

- The audio is synthetic, as described above. Awadhi TTS and STT quality is unverified, and STT is
  not scored.
- Only mp3 output formats are allowed, because the STT upload is labelled `audio/mpeg`.
- TTS and STT are not deterministic, even with `seed`. Only cached audio makes reruns reproducible.
  Live, three unseeded takes of one Awadhi sentence gave three different transcripts, and one of them
  lost the verb रद्द. STT on the same cached audio gave the same transcript on both runs on
  2026-10-18, but that isn't guaranteed.
- STT normalizes what it hears: Latin brand or item words can come back in Devanagari (Kurta →
  कुर्ता), and digits can come back as English words (2 → two). An agent that matches item names or
  numbers by exact string will see that.
- No retries. A 429 or 5xx turns the case into `error`; just rerun it. Concurrency limits depend on
  your plan.
- Only synchronous STT is used: no webhooks, no realtime, no multichannel.
- The evaluator does not yet attribute a failure to `speech_recognition` when `asr_text` differs from
  the utterance. Until it does, compare the two by hand.

## Sources (fetched 2026-10-17, rechecked 2026-10-18)

- Text to speech: <https://elevenlabs.io/docs/api-reference/text-to-speech/convert>. `POST /v1/text-to-speech/{voice_id}` with a JSON body (`text`, `model_id` defaulting to `eleven_multilingual_v2`, optional `seed` 0 to 4294967295) and an `output_format` query parameter (default `mp3_44100_128`; the mp3 values are `mp3_22050_32`, `mp3_24000_48` and `mp3_44100_{32,64,96,128,192}`). The response is the audio. Servers: `api.elevenlabs.io`, `api.us.elevenlabs.io`, `api.{eu,in,sg}.residency.elevenlabs.io`.
- Speech to text: <https://elevenlabs.io/docs/api-reference/speech-to-text/convert>. `POST /v1/speech-to-text` as multipart: required `model_id`, `file` (at least 100 ms, under 5 GB), optional `language_code` (ISO 639-1 or 639-3; null means auto-detect) and `tag_audio_events`. The 200 response has `text`, `language_code`, `language_probability` and `words`. A 202 (`webhook=true`) or a per-channel `transcripts` shape (`use_multi_channel`) only happen for options BoliBench never sends.
- Models: <https://elevenlabs.io/docs/overview/models>. `eleven_multilingual_v2` lists `hi` and accepts up to 10,000 characters per request. `scribe_v2` is the current STT model; `scribe_v1` is listed as deprecated (replacement `scribe_v2`). `eleven_v3` and `eleven_v4` also exist and can be chosen with `ELEVENLABS_TTS_MODEL`.
- STT overview: <https://elevenlabs.io/docs/overview/capabilities/speech-to-text>. Hindi is in the "High Accuracy (>5% to ≤10% WER)" tier. Awadhi is not listed.
- Authentication: <https://elevenlabs.io/docs/api-reference/authentication>. The `xi-api-key` header, plus key scopes, quotas and IP allowlists.
- Errors: <https://elevenlabs.io/docs/eleven-api/resources/errors.md>. JSON `detail` with `type`, `code` and `message` (422 validation errors in the API reference are a list of `{loc, msg, type}`). 401 is authentication, 402 insufficient credits, 429 rate or concurrency limit, 5xx a server error.
