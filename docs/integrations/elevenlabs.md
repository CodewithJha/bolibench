# ElevenLabs speech round-trip

`bolibench.speech.SpeechAdapter` puts speech between the case and the agent. For each user turn:

```
case utterance --TTS--> audio (mp3) --STT--> transcript --> inner agent adapter
```

The inner adapter (webhook, scripted, or any `AgentAdapter`) only ever receives the transcript. The
evaluator does not change: it still judges the sandbox-observed tool calls and final state, and it
does not depend on which provider made the audio or transcript.

Status: tested offline only, against fakes and a local HTTP stub. **No live ElevenLabs call has been
made yet.** See "Live verification" below.

## What it measures, and what it doesn't

It measures:

- whether a code-switched Hindi-English or Awadhi request still leads to the right action after a
  speech round-trip
- what the speech-to-text model heard. Each turn records the transcript next to the original text, so
  you can see where a word was misheard (for example कल heard as परसों) and what the agent did with it.

It does not measure:

- **Real speakers.** The audio is generated by text-to-speech. It does not have real accents, real
  noise, phone-line codecs, disfluencies or speaker variety, so results show synthetic speech
  robustness only, not field accuracy.
- **Awadhi pronunciation.** ElevenLabs lists Hindi as supported, but not Awadhi. Nobody has checked
  how the TTS reads Awadhi Devanagari (for example ओका, कइ दें, रहेन). A native speaker should listen to
  the saved audio before anyone draws conclusions from Awadhi cases.
- **The agent's own speech handling.** BoliBench does the STT itself. An agent that takes audio
  directly is not tested this way.
- **Speech quality.** No word error rate (WER) or audio-quality score is computed. Transcripts are
  evidence for a human to read. They are not scored, and nothing corrects them.

## How the pieces fit

- `TTS` and `STT` are small Protocols, one method each: `synthesize(text) -> bytes` and
  `transcribe(audio) -> Transcript`. Each also has a `config` dict without credentials. Any provider
  can implement them. Tests use fakes.
- `ElevenLabsTTS` and `ElevenLabsSTT` call the HTTP API with stdlib `urllib`, so there are no new
  dependencies. The official SDK isn't needed for two POST requests.
- Each request is tried once: no retries and no redirects (a redirect would send the key to another
  host). Timeouts are bounded (TTS 30 s, STT 60 s by default) and responses have size limits (5 MiB of
  audio, 1 MiB of JSON).
- Any HTTP or network failure raises an `AdapterError`, such as `elevenlabs stt HTTP 429: Too many
  requests`. The runner then gives the case an `error` verdict, never `fail`. A provider outage is
  therefore never counted against the agent.
- An empty transcript (silence) is passed through as-is. A transcript that differs from the utterance
  is also passed through unchanged.

### Evidence per turn

`SpeechAdapter.turns` holds one `SpeechTurn` per turn of the current case: the original utterance,
the transcript text, the detected language and its probability, the audio byte length and sha256, the
audio file path (when an audio directory is used), and the TTS and STT call durations. `tts_s` is
`null` when the audio was reused from the audio directory.

The adapter changes the agent's identity in `AdapterInfo`:

- `name` becomes `speech+<inner name>`
- `config.speech` holds `{"tts": {provider, model, voice, output_format, seed}, "stt": {provider,
  model, language}}`

These are part of the summary's `config_id`, so speech runs and text runs are never grouped together.

The artifacts also get:

- `run.turns[i].asr_text`: the transcript the agent acted on
- `run.turns[i].speech`: the full `SpeechTurn` (omitted in runs without speech, which stay byte-identical)

### Audio directory (audit and cache)

With `audio_dir` (`--speech-audio-dir`), each turn's audio is saved as
`<sha256(tts config, text)>.mp3`. If that file already exists, it is reused instead of calling TTS.
Reruns therefore hear byte-identical audio, and TTS isn't billed again. A different voice, model,
format or seed gives a different key. STT still runs every time. To get fresh audio, use a new
directory. Files are written atomically.

## Setup

1. Create an API key at <https://elevenlabs.io/app/settings/api-keys>. Restrict it to the
   text-to-speech and speech-to-text endpoints and set a credit quota
   ([authentication docs](https://elevenlabs.io/docs/api-reference/authentication)).
2. Pick a voice from your voice library and copy its voice id. Prefer a voice built for Hindi;
   `eleven_multilingual_v2` will speak Hindi with any voice, but accent quality varies.
3. Export the variables below in your shell. Don't put them in files that might be committed.

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `ELEVENLABS_API_KEY` | yes | none | Sent only in the `xi-api-key` header. Never logged, never in artifacts or error messages. |
| `ELEVENLABS_VOICE_ID` | yes | none | TTS voice. There is deliberately no default voice. |
| `ELEVENLABS_TTS_MODEL` | no | `eleven_multilingual_v2` | TTS model id. |
| `ELEVENLABS_STT_MODEL` | no | `scribe_v2` | STT model id. |
| `ELEVENLABS_STT_LANGUAGE` | no | unset (auto-detect) | Language hint for STT, e.g. `hin`. Auto-detect is the fairer test for code-switching. |
| `ELEVENLABS_BASE_URL` | no | `https://api.elevenlabs.io` | E.g. `https://api.in.residency.elevenlabs.io` for India data residency. Must be https. |

The whole config is checked before any network call: a missing key or voice, a malformed id, a
non-https base URL or a non-positive timeout. Through the CLI, any of these is an input error (exit
code 2) and no case runs.

## Running

Python API:

```python
from pathlib import Path
from bolibench.runner import run_case
from bolibench.speech import SpeechAdapter, elevenlabs_from_env
from bolibench.webhook import WebhookAgentAdapter

tts, stt = elevenlabs_from_env()
with WebhookAgentAdapter("http://127.0.0.1:8000/turn") as agent:
    adapter = SpeechAdapter(agent, tts, stt, audio_dir=Path("audio-cache"))
    record = run_case(case, adapter)
    print(adapter.turns)  # per-turn speech evidence
```

CLI (a missing or bad config exits 2 before any case runs; so does `--speech-audio-dir` without `--speech`):

```bash
uv run bolibench run suites/orders --agent-url http://127.0.0.1:8000/turn \
    --speech elevenlabs --speech-audio-dir audio-cache
```

`--speech` also works with `--scripts`. The scripted adapter ignores what it hears, so that run tests
only the round-trip itself: it fills `asr_text` for every case, and the verdicts are the same as a
text-only run.

## Cost

- TTS is billed per character of text and STT per duration of audio. Rates depend on your plan and
  model: see <https://elevenlabs.io/pricing/api>.
- `suites/orders` currently has 12 cases, 14 user turns and 526 characters in total. A full run is
  about 526 TTS characters plus roughly a minute of STT audio.
- `--speech-audio-dir` removes the TTS cost of reruns. STT is billed on every run.
- Don't turn on STT extras such as `keyterms` or `transcript_edit`. They cost extra, and they would
  bias or correct the transcript, which defeats the measurement.

## Live verification (not yet done)

1. Export `ELEVENLABS_API_KEY` and `ELEVENLABS_VOICE_ID` in your shell.
2. Run `BOLIBENCH_LIVE=1 uv run pytest -q -s tests/test_speech.py -k live`. This makes one TTS call and
   one STT call on `awadhi-cancel-yesterday` and prints the utterance, transcript and detected
   language. It is skipped unless the key, the voice id and `BOLIBENCH_LIVE=1` are all set.
3. Run one case with
   `uv run bolibench run suites/orders/ambiguous-previous-order.json --scripts examples/scripts/ambiguous-previous-order.json --speech elevenlabs --speech-audio-dir audio-cache`.
   Check three things: `turns[].asr_text` is filled; the key appears
   nowhere in the output, the artifact or `audio-cache/` (`rg "$ELEVENLABS_API_KEY" runs audio-cache`
   should find nothing); and a second run makes no TTS calls (no new files in `audio-cache/`, and
   `turns[].speech.tts_s` is null).
4. Listen to the saved `.mp3` files for the Awadhi cases and write down what you hear.

Unverified assumptions to confirm in that first live run:

- STT accepts the multipart upload sent as `speech.mp3` / `audio/mpeg`.
- With `tag_audio_events=false`, `text` contains only the spoken words.
- The TTS endpoint accepts `eleven_multilingual_v2` without `language_code`. The docs say that model
  does not support `language_code`, so none is sent.

## Key rotation

1. Create a new key in the ElevenLabs dashboard.
2. Replace `ELEVENLABS_API_KEY` in your shell or secret store.
3. Delete the old key.

Keys are read from the environment on every run and are never stored or cached by BoliBench, and
cached audio files don't depend on the key. If a key may have leaked, delete it in the dashboard
first. A credit quota on the key limits the damage.

## Limitations

- The audio is synthetic, as described above. Awadhi TTS and STT quality is unverified, and STT is
  not scored.
- Only mp3 output formats are allowed, because the STT upload is labelled `audio/mpeg`.
- TTS and STT are not deterministic, even with `seed`. Only cached audio makes reruns reproducible,
  and transcripts can still vary between runs.
- No retries. A 429 or 5xx turns the case into `error`; just rerun it. Concurrency limits depend on
  your plan.
- Only synchronous STT is used: no webhooks, no realtime, no multichannel.
- The evaluator does not yet attribute a failure to `speech_recognition` when `asr_text` differs from
  the utterance. Until it does, compare the two by hand.

## Sources (fetched 2026-10-17)

- Text to speech: <https://elevenlabs.io/docs/api-reference/text-to-speech/convert>. `POST /v1/text-to-speech/{voice_id}` with a JSON body (`text`, `model_id`, optional `seed`) and an `output_format` query parameter (default `mp3_44100_128`). The response is the audio.
- Speech to text: <https://elevenlabs.io/docs/api-reference/speech-to-text/convert>. `POST /v1/speech-to-text` as multipart: required `model_id`, `file`, optional `language_code` (ISO 639-1 or 639-3; null means auto-detect) and `tag_audio_events`. The response has `text`, `language_code`, `language_probability` and `words`.
- Models: <https://elevenlabs.io/docs/overview/models>. `eleven_multilingual_v2` lists `hi` and accepts up to 10,000 characters per request. Scribe v2 supports 90+ languages.
- STT overview: <https://elevenlabs.io/docs/overview/capabilities/speech-to-text>. Hindi is in the "High Accuracy (>5% to ≤10% WER)" tier. Awadhi is not listed. Files up to 3 GB.
- Authentication: <https://elevenlabs.io/docs/api-reference/authentication>. The `xi-api-key` header, plus key scopes, quotas and IP allowlists.
- Errors: <https://elevenlabs.io/docs/eleven-api/resources/errors.md>. JSON `detail` with `type`, `code` and `message`. 401 is authentication, 429 is rate or concurrency limit, 5xx is a server error.
