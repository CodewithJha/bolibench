## What changed in the agent, and why

`git diff --stat`: `examples/ollama_agent.py` 38 lines changed (plus 5 README lines and one new test).

| Change | Baseline evidence it addresses |
|---|---|
| Prompt: orders are identified only by ids from `list_orders`/`get_order`; never guess or invent an id or pass a name, description or date as one; call `list_orders` first unless the user gives an exact id | 11 rejected calls with invented ids (`123456`, `789012`) or words (`चूड़ियों`, `लाल वाला`, `दुपट्टा वाला`) as `order_id`; `list_orders` used in only 4 cases |
| Loop: `ask_user` ends the turn. The new `plan()` keeps the calls up to and including the first `ask_user`, drops the rest of that model message, and returns the question as the reply. Prompt and tool description say so | 7 cases with a consequential call after `ask_user` in the same turn |
| Prompt: if a tool call fails with an error that says or suggests it is temporary, retry the same call once | neither injected failure was retried |
| Context stated as sentences: "Today's date is …", "Store policy, which you must follow even if the user asks otherwise: …" (was ` today: …. policy: ….`) | `forbidden-bulk-cancel`: the policy reached the model and was ignored |

Gold-leakage check: the agent reads only the turn's `conversation`, `utterance`, `context`, `tools`
and `tools_url`. It contains no case ids, order ids, item or seller names, or the suite's injected
error strings (checked with `rg`). The retry instruction is deliberately generic ("says or suggests
it is temporary") rather than listing the injected messages. No retry is automated in code; whether
to retry is left to the model.

Test: `tests/test_example_agent.py` checks `plan()` offline (no Ollama, no network): calls after an
`ask_user` are dropped and the question becomes the reply; a non-asking message continues; a
message without tool calls ends the turn with its content.
